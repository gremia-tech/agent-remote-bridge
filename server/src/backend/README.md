# Host backend

`createHerdrBackend({herdr?, session?, epoch?, configDir?, homeDir?, socketPath?, codexHome?, claudeConfigDir?})` implements `HostBackend` using the public Herdr JSONL Unix socket and installed native terminal helper. An omitted session selects the configured primary (including an inherited named socket). Other sessions are discovered by socket filename under the config root (`$XDG_CONFIG_HOME/herdr`, otherwise `~/.config/herdr`). HERDR_CONFIG_PATH selects a TOML file only and does not relocate Herdr sockets/state. Supplying `configDir` isolates lookup from inherited socket environment; `socketPath` explicitly overrides it. `homeDir` is a fixture/alternate-account override for transcript storage. Custom CODEX_HOME / CLAUDE_CONFIG_DIR values and constructor overrides select the equivalent sessions/projects roots; custom home fixtures ignore the process environment. Always provide the bridge epoch from the secure core.

Snapshots project the native client's existing workspaces/tabs/agents/shellPanes DTOs and add session, socket-generation-bound epoch, boolean capabilities, per-pane identityToken, sanitized process references, and the optional Herdr agentSession object. Identity binds the bridge epoch, Unix socket generation, session, terminal ID, recognized agent, native session reference and process identity. Recognized agents bind the foreground process group; bare-shell panes bind the stable shell PID so ordinary foreground shell jobs retain their lease. Output and transcripts re-check identity after reading. No operation depends on the desktop focus.

0.7.4 supports output, observer/controller streams, literal text, atomic shell text+Enter, workspace/tab creation, splitting and closing. Agent startup and bracketed-paste-aware recognized-agent submission require the known 0.9.5 API semantics. Unsupported old APIs return501. They do not substitute old layout-creating `agent.start` or separate text/Enter calls. `agent.start` accepts Claude/Codex in the requested existing pane, without argv or focus changes. New API field names are checked against pinned Herdr source `5bd900d88c80d95f5b145397e45bbeea398b8165` (`src/api/schema/agents.rs`, `panes.rs`). Version gates are conservative and do not upgrade Herdr.

Terminal observation never owns control or resizes the host terminal. `--takeover` is emitted only for an explicit controlling request with takeover=true. Each stream retains the explicit socket path even when inherited pane/session variables exist. A helper is admitted only after its first valid full frame; native ownership rejection returns409. The secure core monitors live helper/lease identities on its2second sweep and closes them on replacement or host failure; backend writes additionally validate immediately before dispatch. Helpers are subprocesses with explicit socket/config/session environment (helper logs/config/state stay under `.remote-helper` in that root), bounded JSONL buffers, frame checks, input limits, and cleanup. Raw helper commands are terminal.input (text or base64 bytes), terminal.resize, terminal.scroll and terminal.release. Input acknowledgement only means delivery admission. Transport errors after RPC writing are marked deliveryAmbiguous, with no retry.

Files/Git use the extracted MIT inspector with full license and provenance in `server/vendor/herdr-mobile-relay`. Root resolution requires a single trustworthy checkout, refuses filesystem/home roots and multi-repository ambiguity, and enforces symlink/inode boundaries. Git subprocesses are bounded and hardened against hooks, filters, lazy fetch, external diff and repository config execution. The files route returns immediate children, retaining root-relative paths and directory/file kinds. The bridge is independently buildable and does not import research sources.

Transcript access requires an exact reserved native session source (`herdr:codex` / `herdr:claude`) and ID/path. When Herdr has no reference for a Claude/Codex pane (its hook only reports SessionStart), `session-discovery.ts` supplies one from the agent's argv (`codex resume <id>`, `claude --resume <id>`), else, for Codex, from the thread name it writes into the pane title (`<name> | <folder>`; a name current for exactly one thread in `session_index.jsonl`, or for one candidate in the folder), else from interactive sessions in the pane's folder written since the process started (Codex guardian/exec/sub-agent sessions excluded): one candidate in an unshared folder is used directly, several are told apart by a candidate's id printed on screen (Codex's /status panel) or by how many recent message phrases appear in the pane's visible text, and anything ambiguous returns unsupported. Only the first record and the newest MiB of each candidate are read, and nothing from candidates is returned. Candidate search reads filenames only beneath `.codex/sessions` / `.claude/projects`, with a6000-entry/depth5 bound, requires one match and verifies in-file session metadata. Paths outside those roots and symlink escapes fail closed. Codex record shapes are verified against official openai/codex revision d6817454d76885e9d0e118bbf82e507aed6f715a (`codex-rs/protocol/src/models.rs`, `protocol.rs`): response_item messages/function/custom tool records and session_meta.payload.id. Inter-agent agent_message items and unknown logical history formats are not merged. These are local agent log format adapters, not a promise of a stable upstream transcript API. Parsers allowlist response messages and tool calls/results; reasoning, thinking, assistant analysis channels, system/developer prompts, injected metadata, and unknown events are omitted. Fixtures are synthetic. No paid model invocation or private user transcript is needed for validation.

Each transcript page reads at most2MiB and returns at most200 messages/32KiB per text and a normalized payload under approximately1MiB. At most4 transcript reads run concurrently. Session files up to 4GiB are read (pages and tails are bounded, so long-running sessions keep working). Cursors bind pane/native identity, inode and a SHA256 of the consumed content prefix (beyond 8MiB: its first and last 4MiB plus the length, so polling stays cheap). Prefix verification reads bounded chunks and detects interior rewrites, truncation and replacement; malformed cursors reset. Partial final JSON lines wait for completion (`pending:true`, not a pagination truncation, so clients do not busy-loop). Multi-block records are capped with an explicit omission notice and cursor progress. Oversized lines are skipped in bounded chunks. The first page is oldest-first; callers can load additional pages while hasMore=true (also truncated=true for v1 compatibility); pending partial lines do not set hasMore. Session filenames, absolute file locations and source metadata are never returned in the cursor. A `tail=1` first page instead reads whole lines backwards (up to16MiB) until it holds200 user/assistant messages; tool calls and results between them do not count toward that limit, are trimmed to2KiB each, and are shortened to their first line (oldest first) before any message is dropped to fit the ~1MiB payload. Its cursor continues forward from the newest complete line.

Tests: `bun test test/backend*.test.ts test/transcript*.test.ts` from server. Opt-in `HERDR_REAL_TEST=1 bun test test/backend-real.test.ts` requires HERDR_ENV=1 and creates/stops only its own fresh `/tmp/herdr-mobile-real-*` server and shell with separate XDG config/state roots and API/client sockets. It verifies output, first full observer frame, explicit control admission and native controller conflict without takeover. It never controls default/user panes or runs a model turn.
