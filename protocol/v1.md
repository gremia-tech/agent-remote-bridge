# Herdr Remote protocol v1

Implementation contract for the independently paired native client and owner-hosted bridge. Version 1 uses HTTPS REST and authenticated WebSockets. The bridge terminates TLS on the workstation. An optional TCP reverse tunnel forwards these encrypted bytes; it does not terminate application TLS. No proxy-supplied identity header is authentication.

## Pairing and identity

The owner CLI creates a one-use, expiring 256-bit invitation with an explicit `read` or `control` scope. The invitation is JSON `{version:1,url,certificateSHA256,code,expiresAt}` or its base64url encoding under `herdr-remote://pair?data=...`. `certificateSHA256` is the lowercase hex SHA256 of the complete DER leaf certificate. The URL must be a root HTTPS URL without credentials/query/fragment. The app must verify the pinned certificate and its SSL hostname/validity; it must never accept arbitrary certificates.

`POST /v1/pair` body `{code,name}` consumes an invitation atomically and returns `{hostId,hostName,deviceId,token,scope,protocolVersion:1}`. Only the token's hash is stored by the bridge. The app stores the returned credential and pin in ThisDeviceOnly Keychain storage. Failed/expired codes do not reveal which devices exist. Pairing is rate-limited, request sizes are bounded, and invitations are not logged by the HTTP server.

Every other `/v1` operation requires `Authorization: Bearer <device token>`. `GET /health` is unauthenticated and returns only protocol/availability, without project or device data. Cross-origin browser requests are denied. Revocation applies to active sockets and leases, not only new requests. The owner CLI can list/revoke devices and mint new invitations. Tokens are not accepted in URLs.

## Read routes

An omitted `session` selects the bridge's primary Herdr session. All pane/workspace IDs are scoped to host, session and server epoch. IDs and file paths are encoded as URL components/query items.

| Route | Response |
| --- | --- |
| `GET /v1/snapshot?session=` | Existing native `HerdSnapshot` shape plus `hostId`, `session`, `epoch`, `capabilities`; panes add `identityToken` and optional native `agentSession`. Sessions include `isPrimary`. |
| `GET /v1/panes/:id/output?session=&lines=240` | `{paneId,text,truncated,revision,identityToken}`. Rendered output is not conversation history. |
| `GET /v1/panes/:id/transcript?session=&cursor=` | `{paneId,identityToken,source,supported,messages,cursor,reset,truncated}`. Unsupported/ambiguous session binding is explicit. `tail=1` (no cursor) starts from the newest records (at most 200 things said). Additive: a tail page also returns `earlier` (string, or null at the session start); `before=<earlier>` returns the page just before it with its own `earlier` and `cursor:null`, or `reset:true` with no messages when the log before that point changed. Clients send `before` only after receiving `earlier`. |
| `GET /v1/workspaces/:id/git?session=&paneId=` | Native `GitStatus` shape. |
| `GET /v1/workspaces/:id/diff?session=&paneId=&path=` | `{path,patch,truncated}`. |
| `GET /v1/workspaces/:id/files?session=&paneId=&path=` | `{workspaceId,root,entries:[{path,kind}],truncated}`. |
| `GET /v1/workspaces/:id/file?session=&paneId=&path=` | `{workspaceId,path,mediaType,encoding,content,size}`. Workspace-relative and bounded. |
| `GET /v1/operations/:requestId` | `{requestId,state,result?}` where state is `pending`, `accepted`, `failed`, or `unknown`. Device-scoped. |

Transcript messages are `{id,role,kind,text,timestamp?,toolName?}`. `role` is `user`, `assistant`, `tool`, or `system`; `kind` is `message`, `tool_call`, `tool_result`, or `notice`. Expose published messages/tool activity only, not hidden reasoning. A cursor binds source session/file identity and captured content prefix; mismatches return `reset:true`. Parse on the host so clients share fixes. Harness-injected user-turn content (instructions, environment and status blocks such as `<environment_context>` or `<task-notification>`) is never projected as something the user said; status blocks may appear as short `notice` messages. When the multiplexer has no session reference for a Claude or Codex pane, the host may locate the log itself: a session id on the agent's command line, else an interactive session in the pane's folder written since the agent started, disambiguated by matching the pane's visible text; ambiguity yields `supported:false`, never another pane's conversation.

## Explicit control

`POST /v1/panes/:id/control?session=` body `{identityToken,takeover:false}` returns `{leaseId,paneId,identityToken,expiresAt}`. Only a control-scoped device may acquire a lease. A conflicting controller yields 409; taking over requires a separate explicit request with `takeover:true`. The backend starts the Herdr controller only after acquisition. Opening/observing a pane never claims input, changes desktop focus or resizes the host terminal.

`POST /v1/control/:leaseId/renew` extends a live lease owned by the device. `DELETE /v1/control/:leaseId` releases it. Leases expire after a short idle window and are released on revocation or bridge shutdown. Missing/expired/wrong-device leases fail closed.

`POST /v1/panes/:id/input?session=` body `{requestId,leaseId,identityToken,text?,bytes?,keys?,submit?}` accepts exactly one input representation. `text` is literal UTF-8; `bytes` is base64; `keys` is an allowlisted array of logical keys. `submit:true` is supported for text only and uses a bracketed-paste-aware atomic Herdr operation where advertised. Validate current pane identity before dispatch. No automatic approval action is inferred from a `blocked` status.

Mutations require a UUID requestId. Persist the body digest and pending operation before dispatch. Same ID/body returns its existing result; a changed body is 409. Pending operations from a previous bridge process become `unknown`, never automatically execute again. A response means input admission, not completion of the agent's task. After a network timeout the native client checks the operation record; it never blindly resubmits input.

Structural writes use `POST /v1/workspaces` `{requestId,cwd,label?}`, `POST /v1/tabs` `{requestId,workspaceId,label?,cwd?}`, `POST /v1/panes/:id/split?session=` `{requestId,identityToken,direction:"right"|"down",cwd?}`, `POST /v1/agents` `{requestId,paneId,identityToken,kind,name}` and `DELETE /v1/panes/:id?session=` with JSON `{requestId,identityToken}`. They require control scope, current explicit targets, no focus changes by default, bounded arguments and an adapter capability. Unsupported older-server operations return 501, rather than silently changing command semantics.

## Same-network discovery and pairing (additive)

A host started with `up` or `serve --discoverable` advertises Bonjour service `_agentremote._tcp` with TXT `v=1`, `id=<hostId>`, `pin=<certificateSHA256>`, `url=<root HTTPS URL>`, `pair=code|off`. The record is a hint: clients pin `pin` exactly as for an invitation and must not treat the advertisement as authentication. A saved host whose `hostId` and pin match may use the advertised URL for that connection.

`POST /v1/pair/nearby` `{name}` (unauthenticated, rate-limited per address, at most four pending) shows a random 6-digit code on the computer and returns `{requestId,expiresAt}` (two minutes). `POST /v1/pair/nearby/confirm` `{requestId,code}` returns the `/v1/pair` response with the host's configured nearby scope (control by default). A wrong code is 403 `invalid_code`; the request is discarded after five attempts or expiry (410). Hosts without discovery return 501 `unsupported`.

## Live terminal

`GET /v1/live?session=` upgrades with the Authorization header. Client messages: `{type:"observe",paneId,identityToken,cols,rows}`, `{type:"unobserve"}`, `{type:"resize",leaseId,cols,rows}`, `{type:"scroll",leaseId,direction,lines}`. Observation uses the Herdr read-only helper; input remains REST so durable request IDs apply. Dimensions are bounded to 20–400 columns and 5–200 rows.

Additive (snapshot `capabilities.hostSizedTerminal`): `observe` may send `fit:"host"` instead of `cols`/`rows`. The host then streams the pane at its exact pseudo-terminal size and restarts the stream with a new full frame when the computer resizes the pane; clients render `width`×`height` and scale it, never crop. Control leases attach at the pane's current size. `resize` may send `fit:"host"` to return to that size; a pane resized by a phone is restored to it when the lease is released.

Additive (`capabilities.liveInput`): `{type:"input",leaseId,bytes}` delivers interactive keystrokes (base64, at most 12,000 characters) to the pane this socket controls. Socket input is delivered at most once and never journaled or retried: a dropped socket loses unsent keys instead of replaying them. Prompt submission and other commands keep the durable REST path. `snapshot_changed` is sent only when the session snapshot changes.

Server messages: `{type:"connected"}`, `{type:"snapshot_changed"}`, `{type:"pane_frame",paneId,identityToken,seq,full,width,height,bytes}`, `{type:"stream_closed",reason}` and `{type:"error",code,message}`. `bytes` is base64 ANSI. A socket associated with a lease can receive controller frames after explicit acquisition; observation alone stays read-only. Keep queues bounded, close/resynchronize on missing frames or excessive backpressure, and start a new stream with a full frame. Server generations and pane identity changes invalidate old streams.

## Errors and limits

Errors are JSON `{error:{code,message},deliveryAmbiguous?}`. Use 400 validation, 401 invalid/revoked credentials, 403 scope/origin, 404 missing resources, 409 identity/ownership/body conflict, 410 expired invitation/lease, 413 size, 429 rate limit, 501 unsupported capability and 503 host unavailable. Never put prompts, tokens, invitation codes or file contents into default audit records. Single-user OS ownership is the host trust boundary; terminal control has that user's command authority.

## Optional notifications

`POST /v1/notifications` registers `{token,environment:"sandbox"|"production"}` for the authenticated device, and `DELETE /v1/notifications` removes registration. A host without a configured provider returns501 on registration. No registration occurs without an explicit native permission action. Alerts contain generic text and an opaque hostId only; they are hints to reconnect, never approval requests or authoritative command state. Public-app publisher keys must not be shipped to self-hosters; see the deployment notes for the remaining gateway release decision.

See [private connection invitations](connection-routes.md) for optional v2 route metadata. The application API remains version1.

## Backend identity (additive)

A snapshot may include `backend: {kind: "herdr" | "orca" | "plain", name, version?, controlScope?}`. `plain` is a bridge that runs its own shells (no multiplexer): workspaces are folders, each tab holds terminals the bridge spawned, agents are recognised from a terminal's foreground program, statuses are `unknown`, and `transcript` serves a recognised agent's own session log when the bridge can find it (otherwise `supported:false` and clients read the terminal). `capabilities.agentKinds` (optional string array) lists the agent kinds `POST /v1/agents` accepts on this host; clients fall back to `["claude","codex"]` without it. Missing identity means the legacy Herdr projection. Backend selection is host configuration, never a phone-supplied arbitrary RPC destination. Protocol1 and direct/v2 route invitations remain compatible. See [Orca adapter](../server/src/backend/orca/README.md).

`controlScope: "native"` uses Herdr's native controller ownership; `"bridge"` coordinates companion devices while Orca's desktop/native clients may still interact. Clients must retain explicit leases, identity checks and no uncertain replay for either. `transcript: false` means live output remains available without inferred conversation bindings. `agentStart: false` hides unsupported startup. Orca workspace creation imports an existing local repository; it does not promise isolated worktree creation. File/Git access can refuse unproven remote execution roots.
